---
title: Commit Model
description: How Persistent Dir writes move from an isolated session into app storage.
---

Persistent Dir writes should happen in two phases:

1. The agent writes files inside the isolated session.
2. Little Harness commits changes to developer-backed storage at a defined boundary.

The default boundary for agent and tool work is after each agent turn.

## After-Turn Commit

An agent turn is one full response to one input, including tool calls, shell commands, subagents, generated artifacts, and model output.

```ts
persistentDirs: [
  {
    harnessDir: "/persistent/user",
    load,
    store,
    commit: "after-turn",
  },
]
```

After the turn, the runtime computes a diff and calls `store`.

## Host-Staged Writes

Host-staged writes can happen without a model turn.

```ts
await session.files.write("/persistent/user/uploads/report.pdf", stream);
```

If the path is inside a Persistent Dir, Little Harness should still write into
the isolated session first. Then it can commit that one host operation
immediately, because there may be no next agent turn.

If the commit fails, the file remains recoverable in the session workspace and
the host operation receives the failure. The model should not receive that
failure automatically.

## Why Not "Session Done"

"Session done" is not a reliable event. A user can close a tab, a phone can background the app, a serverless function can end, or a network request can disconnect.

After-turn commits give a predictable boundary that works for chat, jobs, and APIs.

## Commit Failures

Commit failures are host-facing runtime events. They should be recorded in the trace and exposed on the result.

```ts
const finished = await result.finished;

if (finished.persistence.status === "failed") {
  await retryQueue.enqueue(finished.persistence.failedCommits);
}
```

The model should not receive automatic commit failures in its normal context. The agent already finished the turn, and the host app is better positioned to retry or warn the user.
