---
title: Persistent Dirs
description: Cross-session files backed by developer-provided storage logic.
---

Persistent Dirs are opt-in directories whose files can survive beyond one session.

Harness memory is a convenience layer on top of this model. `memory(...)` creates
a normal Persistent Dir, adds a bounded memory index to future prompts, and can
add the built-in `remember` tool for model-authored durable notes.

They are not global scratch folders. They are developer-backed harness directories: the app decides how to fetch and store files, and Little Harness handles the safe session directory, diffing, tracing, and commit boundary.

```ts
persistentDirs: [
  {
    harnessDir: "/persistent/user",
    load: async ({ extraBody }) =>
      appStorage.loadFolder(`users/${extraBody.userId}/memory`),
    store: async ({ extraBody, changes }) =>
      appStorage.applyChanges({
        prefix: `users/${extraBody.userId}/memory`,
        changes,
      }),
  },
]
```

## Load

`load` runs before the agent uses the Persistent Dir. It returns the files Little Harness should expose at `harnessDir` for this session.

For simple apps, that can be a folder snapshot. For larger stores, future adapter shapes may load lazily.

## Work

The agent edits the `harnessDir` inside the isolated session. The backing store is not mutated on every write.

```txt
/persistent/user/preferences.md
/persistent/user/research-notes/acme.md
```

## Mixed Sources

One harness can expose several Persistent Dirs with different backing sources
and write policies.

```ts
persistentDirs: [
  localDir({
    harnessDir: "/persistent/company",
    sourceDir: projectDir("./docs/company-knowledge"),
    commit: "read-only",
  }),
  localDir({
    harnessDir: "/persistent/user",
    sourceDir: ({ extraBody }) =>
      `persistent/users/${extraBody.userId}/memory`,
    commit: "after-turn",
  }),
]
```

The `read-only` company directory rejects writes immediately. The writable user
directory accepts changes in the session first, then commits them after the turn.

Little Harness does not infer sharing or read/write policy from names such as
`company`, `project`, or `user`. The developer controls the backing source and
commit mode for each directory.

## Commit

At the end of the agent turn, Little Harness computes the diff and calls `store`.

If the commit fails, the failure is host-facing. It should be visible in the result and trace, not injected into normal agent context.

```ts
const result = streamHarness({ harness, messages, session, extraBody });
const finished = await result.finished;

if (finished.persistence.status === "failed") {
  // Host app decides whether to retry, warn, or escalate.
}
```
