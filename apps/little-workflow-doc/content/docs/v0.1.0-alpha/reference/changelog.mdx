This page summarizes the changes that matter to Little Workflow users. The full, authoritative history for both `little-workflow` and `little-harness`, which are released together, is the repository [CHANGELOG.md](https://github.com/samuelch727/little-workflow/blob/main/CHANGELOG.md). These docs keep the `v0.1.0-alpha` URL path for stable links, but they describe the current release.

Little Workflow is in its **alpha phase**: the LWIR wire format, public APIs, and persistence formats can change between alpha releases.

## 0.2.0-alpha.0

The first npm release since `0.1.0-alpha.1`, and the first Apache-2.0 release on npm. Install with `pnpm add little-workflow@alpha ai@^7 zod @ai-sdk/<provider>`.

### Breaking changes

- **AI SDK 7 and Node.js 22.** `ai` is now a peer dependency (`^7.0.0`) instead of a bundled one, so install `ai@^7` and an AI SDK 7 provider package. AI SDK 6 is no longer supported, and Node.js 22 or later is required.
- **Tool context key.** Code that reads `callerRunIdentity`, `sequenceIndex`, `modelStepId`, or a workflow `signal` inside a tool must read it from the AI SDK 7 `context` execute option instead of `experimental_context`.
- **Workflow run storage under a harness.** Runs started from a Little Harness agent are stored under the harness session's data directory (`<dataDir>/sessions/<session>/workflows`), not `<cwd>/<sessionId>/workflows`. Runs recorded under the old path are not found on resume.
- **Orchestrator deprecated** (`LWF_DEP_ORCHESTRATOR`). `runWorkflow({ workflows: [...], orchestrator })`, the `plan_workflow` / `run_workflow` / `start_workflow` tools, `createOrchestratorTools`, and `workflowSnapshotsForOrchestrator` still work but emit a one-time `DeprecationWarning`. Compose with `defineWorkflow` → `asHarnessWorkflow` → `createHarness({ workflows })` instead; see [Compose With Little Harness](/docs/v0.1.0-alpha/authoring/compose-with-harness).
- **Stricter LWIR.** Declared-but-unimplemented fields are rejected with `schema.unimplemented_field` instead of being accepted and ignored. These are non-empty `permissions.secrets` / `permissions.network`, `onFailure.repair.mode: "escalate"`, `onFailure.repair.model`, and step `cache`. Records keyed by a non-string schema (`z.record(z.number(), V)`) are rejected.
- **Pinned scaffolds.** `little init` / `little add` write the CLI's own version and AI SDK 7-compatible ranges instead of `latest`.

### Added

- **`defineWorkflow`** with a typed `runWorkflow(definition, input)` and `definition.run(input)`, plus folder workflows (`little-workflow.json` + `workflows/<name>/workflow.ts`) loaded with `loadWorkflow`.
- **`asHarnessWorkflow`** adapts a workflow into a Little Harness tool. It accepts a `defineWorkflow` result directly and requires `definitionIdentity`.
- **Workflow tool results** carry an `outputSummary`, a compact rendering of the output capped at 4,096 characters, so the calling model sees what the run produced.
- **Bounded fan-out** on the Harness surface. `workflowBudgets.maxConcurrentWorkflowRuns` / `maxQueuedWorkflowRuns` bound inline workflow-tool calls with a FIFO queue.
- **Dynamic workflows.** `dynamicWorkflows()` lets a Little Harness agent author and run a one-shot step-DAG plan.
- **Real USD costs** per step, session, and run (`RunResult.usage.costUsd`, `runReport` / `formatRunReport`, `priceModelCall`), from a bundled model registry with pricing provenance and a staleness gate.
- **CLI:** `little init`, `little add workflow|harness`, `little test`, and `little report` (JSON or `--table`). `little init --help` and `little add --help` print usage.
- **Schemas:** the annotation keywords `description`, `title`, and `examples` are accepted, so `.describe()` works. `propertyNames` is accepted for string- and enum-keyed `z.record(...)` and enforced at run time.
- `lwir-input-cone@v1` (`inputConeHash` / `inputConeSnapshot`) and experimental eval-set bundles with a local content-addressed store.
- `ai.generate` steps repair malformed structured output themselves.

### Changed and fixed

- The AI SDK adapter targets AI SDK 7: `instructions` instead of `system`, and `usage` as the all-steps total.
- Cached input and reasoning tokens are read from AI SDK 7's `inputTokenDetails` / `outputTokenDetails`. Before this fix, cached input was priced at the full rate.
- Registry prices were corrected and delisted models removed.
- `little init` writes `pnpm.onlyBuiltDependencies: ["better-sqlite3"]` so pnpm 10 builds the event store's native binding. `little init` / `little add` reject unknown options.
- Package exports use the `default` condition and expose `./package.json`.

## Earlier releases

- **0.1.0-alpha.2** (tagged, never published to npm) relicensed the project under Apache-2.0.
- **0.1.0-alpha.1** was the initial public alpha. It included workflow authoring, planner compilation, LWIR validation, durable Local World execution and replay, and the `little` CLI.

See the [Roadmap](/docs/v0.1.0-alpha/roadmap) for direction beyond the alpha.
