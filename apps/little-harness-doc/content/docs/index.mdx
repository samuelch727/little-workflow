---
title: What Little Harness Is
description: A zero-config agent runtime for tools, skills, files, traces, and isolated sessions.
---

Little Harness is an agent runtime for apps that need agents to use tools, skills, files, and scripts without making the developer design the sandbox, storage, artifact, or tracing layer first.

The developer-facing contract stays small: provide instructions, tools, optional skills, optional workflows, and optional Persistent Dirs. Little Harness creates the session workspace, isolates it from other sessions, stores large outputs as artifacts, records a trace, and returns a result. A `workflows` option lets the agent trigger a Little Workflow as a typed tool.

```txt
app request
-> Little Harness session
-> isolated workspace + skills + tools + artifacts
-> optional Persistent Dirs
-> assistant result + trace + persistence status
```

## Product Boundary

Little Harness is:

- a local-first agent runtime
- an isolated session workspace
- a tool and skill harness
- an artifact-first file surface
- a trace and persistence boundary
- a first runtime target for just-bash

Little Harness is not:

- a workflow compiler
- a chat UI
- a requirement to adopt Little Workflow
- a reason to expose arbitrary host paths to the model
- a requirement that developers define containers or microVMs before their first agent works

## Where It Sits In The Stack

Little Harness is the SDK half of the Little stack, with Little Workflow. You
build the agent here; LittleDB, the product, traces what the agent does, scores
it (code checks, AI judges, people, and what your users said), and improves it
by testing a proposed change on your own past conversations before it goes
live. Harness needs nothing from LittleDB to run, and the connection is one
`onEvent` hook; see [Using LittleDB](/docs/v0.1.0-alpha/reference/using-littledb).
LittleDB is private source for now.

An agent's work lives in a **workspace**: each user's own folder, kept between
visits. Most turns run on the folder tier, which is Harness's own just-bash
sandbox over the user's files, and a container joins only when a command needs
a real machine (git, a package manager, a build, tests), as the `nextTier` of
[`tieredSandbox()`](/docs/v0.1.0-alpha/runtime/execution-tiers). Managed
workspaces come with LittleDB's hosted service (private for now), and
self-hosted ones with Little Compute; the same agent folder runs on a laptop or
a Podman box today and on the managed service as it lands, and only the sandbox
builder differs.
