---
title: Filesystem Model
description: How the runtime exposes session, artifact, skill, and persistent files.
---

Little Harness should expose a stable virtual filesystem to the agent, even if the backing implementation changes later.

```txt
/session/
/artifacts/
.agents/skills/
/persistent/
```

Every mounted root should emit a `filesystem.mounted` trace event at the start
of a turn. The event records file paths, file kinds, byte counts when known, and
whether the root is writable. It does not record raw file contents.

## `/session/`

The private workspace for one session. It is writable by the agent and persists across turns in that session.

Use it for:

- staged user uploads
- app-staged context files
- notes
- temporary scripts
- intermediate datasets
- draft reports

The host app can write here through `session.files`, message staging can write
here through `chat.stageMessage`, and tools can write here through `ctx.files`.
Those writes should be traced like model-created file changes.

For text files, `file.created`, `file.updated`, and `file.deleted` events should
include before/after byte counts and hashes. `file.updated` should include a
bounded unified diff when the diff is small enough to inline:

```json
{
  "path": "/session/notes.md",
  "root": "session",
  "source": "agent",
  "before": {
    "bytes": 28,
    "sha256": "3d2c4a1a6c1f2a2f0e8070f6354c0c7376aeb57c4a7499c06f917f780cf5f7c4"
  },
  "after": {
    "bytes": 44,
    "sha256": "cd40a2a40f0c138afdf01fd497de47e264b192b8cf0cfceff3da839f8917b0ef"
  },
  "diff": {
    "available": true,
    "format": "unified",
    "preview": "@@ -1 +1\\n-old note\\n+new note\\n",
    "truncated": false
  }
}
```

Large diffs should use `/artifacts/trace/...` content refs. Binary files should
record metadata and `diff.available: false`.

## `/artifacts/`

The artifact surface for large outputs and generated files. Tool outputs, transformed datasets, and final reports can live here until exported.

Artifacts should have trace entries so the host app can inspect what was created and why.

Trace artifacts live under `/artifacts/trace/...`. Tool results that are too
large to send inline to the model live under `/artifacts/tool-results/...`.
Both are normal artifacts: the host can list them, and the model can read them
when it receives a harness path.

## `.agents/skills/`

Read-only skill content. The model can discover a skill from prompt-visible metadata, then read the full body from this directory when needed.

```bash
cat .agents/skills/frontend-design/SKILL.md
```

The trace records which skill files were mounted by path and size. It does not
duplicate `SKILL.md` bodies into `trace.ndjson`.

## `/persistent/`

Opt-in cross-session directories backed by developer-provided storage logic.

Each Persistent Dir has a `harnessDir`, such as `/persistent/user`, and a separate backing source, such as a Local Host `sourceDir`, an S3 prefix, or custom `load` and `store` callbacks.

The runtime should expose the `harnessDir` inside the session. Writable Persistent Dirs buffer writes until the commit boundary; read-only Persistent Dirs reject writes immediately. The app's backing store should not be mutated on every shell write.

Persistent Dir loads and commits should be traceable separately from ordinary
file writes:

- `persistent_dir.loaded` records the mounted `harnessDir`, commit policy, and
  file count.
- file events record edits inside the session checkout.
- `persistent_dir.commit.started`, `.succeeded`, and `.failed` record the commit
  boundary and storage result.

Commit failures are host-facing control-plane events. They are not automatically
injected into the model's normal context.

## No Arbitrary Host Paths

The model should not receive raw host filesystem paths by default. If a developer wants to expose local files, they should do it through `projectDir(...)`, a tool, or a Persistent Dir adapter.

Local Host may expose local debug paths to the host app and CLI, but those paths
should not become model-visible content unless the developer explicitly stages
or mounts them through the harness filesystem.
