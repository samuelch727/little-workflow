`v0.2.0` is the high-throughput release. The crash-consistent runtime from v0.1.0 keeps its shape; what arrives is the fan-out and reducer story for workflows that need to process many items, plus the plugin and module surface that lets a community extend the runtime.

## Compared To v0.1.0

The authoring surface from earlier versions still works. v0.2.0 layers on capabilities that did not exist before, none of which break existing workflows.

## New Step Types And Topology

- Sharded fan-out for foreach steps. Items are distributed across shards with deterministic batching keyed by `f(shardId, level)`.
- Tree reducers that compose intermediate reducer outputs as cacheable artifacts keyed by `sideEffectKey(reducer:level:batch)`.
- Custom step type plugins. Step executor signatures stay Promise-based; Effect remains internal.

## New Ecosystem Surface

- Storage, queue, sandbox, and telemetry adapter packaging. Adapters become installable packages with manifest hashes that join the WorkflowVersion lock.
- Third-party UI inspector panels. Each panel runs in a sandboxed iframe with explicit policy on which run data it can read.
- Remote and private SkillPack registry support, with content-addressed locks at registration time.
- Remote and private plugin registry support, with the same content-addressed locks.
- Workflow modules — packageable units that include a workflow definition plus locked tools, skills, and policy.
- Marketplace-oriented package distribution flows.

## New Observability

- Expanded dashboard views for fan-out, pipelines, cost, replay, and fork.

## Still Not In This Version

- Visual workflow editing — arrives in [v1.0.0](/docs/v1.0.0).
- Multi-tenant organization controls, autoscaling, enterprise audit exports, evidence graphs, evaluation suites — all in [v1.0.0](/docs/v1.0.0).
