Little Workflow is artifact-first and event-driven. The runtime stores facts in the event log and payloads in artifact storage.

## Minimum Events

```txt
OrchestrationRequested
PlannerStarted
PlannerDraftedWorkflow
WorkflowValidationFailed
WorkflowValidationSucceeded
WorkflowCostEstimated
WorkflowVersionRegistered
RunStarted
StepScheduled
StepAttemptStarted
ModelCallStarted
ModelCallCompleted
ToolCallStarted
ToolCallCompleted
ArtifactCreated
StepOutputValidated
StepCompleted
StepFailed
RunCompleted
RunFailed

```

```json
{
  "eventId": "evt_123",
  "runId": "run_456",
  "type": "StepCompleted",
  "stepPath": "review-candidates.extract-profile",

    "outputTokens": 918,
    "costUsd": 0.018
  }
}
```


## Retry, Replay, Fork

Retry re-executes a failed step using the same WorkflowVersion and input. It requires idempotent commits or explicit side-effect policy.

Replay reconstructs state from event history. It does not call models, tools, shell, code, or external APIs.

Fork creates a new run from a checkpoint or previous run. It can change workflow spec, input, model slot mapping, prompt, policy, or output schema while preserving provenance.
