> **Preview — not yet available.** `@little-stack/littledb` is **not published to npm**, and it needs a LittleDB server that is not public. This page describes the client as it exists in the repository (`packages/littledb-client`) so you can see the API ahead of release. You cannot install it today, so use the default [Local World](/docs/v0.1.0-alpha/running/local-world).

LittleDB is an optional service that stores traces and their scores, holds the versions of your agents and workflows, and runs experiments on them. Its client connects with one URL and one API key, and wraps any Little Workflow `World` so each run is also sent to LittleDB as a trace.

## Install

Not available yet. The package is private to the repository until LittleDB is public; there is no npm package to install.

## Use (preview)

```ts
import { localWorld, runWorkflow } from "@little-stack/workflow";
import { createLittleDB } from "@little-stack/littledb";

const db = createLittleDB({ url: process.env.LITTLEDB_URL!, apiKey: process.env.LITTLEDB_API_KEY! });

const world = db.tracingWorld(localWorld({ dataDir: ".little-workflow" }), {
  workflow: "lending.preapproval",
});

const result = await runWorkflow(myWorkflow, myInput, { world, tools });
await db.shutdown(); // in a script: send what is queued before the process exits
```

The wrapper is still the inner World: reads, artifacts, recovery and replay go to it, and it stays the source of truth. It watches the events the runtime appends and sends each run as one trace (`lw_<runId>` by default): the run is the root span, each step attempt a child, and model and tool calls sit under the step that made them, with token usage so LittleDB can price them. Traces are queued and sent in the background; a LittleDB that is down never fails a run.

## Options

- **`workflow`** — the workflow's slug in LittleDB. Required.
- **`origin`** — `code` (default), `agent` (`define_workflow`) or `planner` (a one-shot plan).
- **`resolution`** / **`versionId`** — the LittleDB version the run uses, from `db.resolve({ kind: "workflow", ... })` or as an id.
- **`harness`**, **`userId`**, **`environment`**, **`tags`**, **`metadata`** — added to the trace.
- **`sessionId`** — the session the run belongs to. A run started by a harness tool call already carries it in its `trigger`, so set this only to override it.
- **`traceId`** — a fixed trace id, or a function of the run id.
- **`captureContent`** — `false` sends structure and numbers only.

## Agent-made workflows

`dynamicWorkflows({ world })` takes a World, or a function that picks one per run, for the runs of workflows an agent defines and of one-shot plans. Wrap the default store to trace them:

```ts
dynamicWorkflows({
  world: (run) =>
    db.tracingWorld(localWorld({ dataDir: run.dataDir }), {
      workflow: run.handle,
      origin: run.kind === "defined" ? "agent" : "planner",
    }),
});
```

Each such run records how it started (`trigger: { kind: "harness", sessionId, turnId, toolCallId }`), so its trace carries the session and points at the turn's trace and the tool call that started it. Pass `runWorkflow(..., { trigger })` to record your own (a webhook, a cron job); a sub-run points at its parent run.

LittleDB's `db.agentWorkflowRegistry({ harness })`, passed as `dynamicWorkflows({ registry })`, makes each definition a draft version in LittleDB with a proposal a person approves; a turn then offers approved versions, plus the session's own drafts.

LittleDB is optional. Little Workflow works with the default Local World without it.
