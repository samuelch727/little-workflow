`v0.1.0-alpha` is the minimum implementation that proves the thesis: a developer-supplied control plane compiles to validated LWIR and executes durably enough for a local development loop, with an AI agent running in a structured **Harness** to design, compose, and execute workflows.

## What This Version Includes

**Harness-based execution**

- `Harness` contract — the agent-runtime primitive (`run(task, ctx): Promise<HarnessResult>`)
- Default `workflowHarness` — model + bash env + scoped storage + agent loop; substitutable (Cloudflare Workers, custom infra)
- Unified event vocabulary: `harness.session.started, harness.session.completed`, `harness.model.called, harness.model.responded`, `harness.tool_call.started, harness.tool_call.succeeded, harness.tool_call.failed`

**The four roles**

- **Planner** — harness session that designs LWIR for one workflow run; has bash, memory, scratch, and skills
- **Orchestrator** — harness session that composes multiple workflow definitions together via `plan_workflow` / `run_workflow` / `start_workflow` tools; spawns parallel sub-runs with plan-once-run-many pattern
- **Worker** — harness session (or direct-execute) for each LWIR step; unified across `ai.generate`, `code.run`, `tool.call`, and `decision` step types
- **Fixer** — per-step opt-in harness session that self-heals failed `code.run` steps before escalating

**Workflow composition**

- Polymorphic `runWorkflow`: single `WorkflowDefinition` → planner session; array of definitions → orchestrator session
- `plan_workflow` / `run_workflow` / `start_workflow` orchestrator tools; up to `maxConcurrentSubRuns` parallel sub-runs
- Plan-once-run-many: one planner call for N parallel sub-runs sharing the same LWIR shape

**Memory and context**

- **Memory Stores** at `/mnt/memory/{workflow,pipeline,org}/` — persistent, filesystem-shaped, Anthropic-aligned; rw/ro per scope
- **Run Scratch** at `/mnt/scratch/{own,from-orchestrator,from-planner,peer-steps}/` — ephemeral top-down context passing within a run
- **Skills** — `SKILL.md` packages materialized at `.agents/skills/<name>/`; metadata and read instructions are added to the initial prompt, and bodies are read on demand by Planner, Orchestrator, AI Worker, and Fixer

**Identity and durability**

- `WorkflowDefinitionHash` (authoring-time identity, stable across runs) distinct from `WorkflowVersion` (per-run LWIR hash)
- Three manifests (`OrchestratorManifest` / `PlannerManifest` / `WorkerManifest`) stored in `harness.session.started` events; fail-closed on drift
- Per-step memoization extended to the harness session level — model calls AND tool calls are event-logged; deterministic fast-forward on resume

**LWIR and execution**

- LWIR unchanged — step types `ai.generate`, `code.run`, `tool.call`, `decision`, `parallel`; expressions, validator, and repair loop
- `code.run` step signature: `async ({ input, tools }) => output` — code bodies can invoke registered tools directly without model in the loop
- AI SDK `tool({...})` as the canonical tool primitive; MCP via `experimental_createMCPClient`
- Local World only — SQLite/WAL event storage, artifact manifests, and local run locks
- Minimal CLI: `validate`, `run`, `events`, `replay`
- Kill-and-resume demo

## What This Version Does Not Include

- **Dreaming** — consolidating memory across many sessions (post-alpha; implementable as a workflow using these same primitives)
- **Cost and budget enforcement** at sub-workflow boundaries (cost observability is in alpha; enforcement is not)
- **Memory versioning and audit log** — alpha uses plain files + mtime; explicit version objects and `content_sha256` preconditions come post-alpha
- **Run-time skill injection** via `RunWorkflowOptions.skills` — alpha supports workflow-declared and org-mounted skills only
- **OpenRouter model registry sync** — alpha ships a bundled registry; live OpenRouter fetch is post-alpha
- **Approval workflows**, structured memory query tools, and recursive pipelines — post-alpha
- **Streaming harness session events** to `runWorkflow` callers — sessions stream internally; the caller receives final output
- Production durability (Postgres, Redis, S3), the full capability firewall, OpenTelemetry, sharded fan-out, tree reducers, custom step types, and visual editing arrive in later versions
