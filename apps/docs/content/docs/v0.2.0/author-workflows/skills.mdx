---
title: Skills
description: Simple reusable guidance files without granting capabilities.
---

Little Workflow uses the Agent Skills `SKILL.md` convention for reusable procedural knowledge.

Skills are context, not authority. A skill can teach the planner or worker how to use a rubric, schema, workflow, or tool. It cannot grant model access, tool access, network access, secrets, shell access, or storage access.

## Skill Shape

```txt
candidate-review/
  SKILL.md
  references/
    evidence-rubric.md
    redaction-rules.md
  schemas/
    evidence.schema.json
  assets/
    scorecard-template.json
  scripts/
    validate-evidence.ts
```

`SKILL.md` contains YAML frontmatter plus instructions:

```md
---
name: candidate-review
description: Use when evaluating candidate materials and extracting evidence.
---

Compare candidate evidence against the hiring rubric.
Prefer page-span evidence references over free-text quotations.
```

## Register A Skill

Register skills directly by file path:

```ts
const runtime = createRuntime({
  world: localWorld(),
  skills: [
    skill("./skills/candidate-review/SKILL.md"),
    skill("./skills/brand-voice/SKILL.md"),
  ],
});
```

The runtime can read the `name` and `description` frontmatter to decide when the skill is useful. When a workflow uses a skill, the run should record which skill file and content hash were used so replay and audit can show what guidance was present.

## Keep Skills Small

Use skills for reusable instructions, examples, and references. Keep capability decisions outside the skill:

- a skill may recommend a tool, but it cannot grant tool access
- a skill may describe a network resource, but it cannot grant network access
- a skill may include helper files, but it cannot execute them by itself
- a skill may explain a process, but runtime policy still decides what a workflow can do
