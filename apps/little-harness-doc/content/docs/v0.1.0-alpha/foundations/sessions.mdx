---
title: Sessions
description: How Little Harness creates, resumes, and isolates agent sessions.
---

A session is the durable boundary for one agent conversation or job. In the alpha API, `streamHarness()` and `generateHarness()` can create an ephemeral session or continue a stable app-provided session key.

```ts
const result = streamHarness({
  harness,
  messages,
});
```

The app can ignore sessions for one-shot work, or pass a stable id to continue the same workspace. The same rule applies to non-streaming calls.

```ts
const result = streamHarness({
  harness,
  messages,
  session: chatId,
});
```

```ts
const result = await generateHarness({
  harness,
  type: "account.brief",
  input: { accountId },
  session: jobId,
});
```

## What A Session Owns

A session owns:

- the model context policy (the transcript is caller-owned: the client resends
  `messages[]` each turn, and the session does not store it)
- a private `/session/` workspace
- host-staged files for future turns
- artifact references created during the session
- Persistent Dir checkouts and uncommitted changes
- trace events

## Concurrency Rule

One session never runs more than one turn at the same time.

If two requests target the same session, the host serializes them. Local Host
queues same-session calls by default and can reject them when configured to do
so. Different sessions can run concurrently.

## Out-Of-Band File Staging

The app can add files to a session without pretending those files are a chat
message.

```ts
const session = await harness.sessions.getOrCreate({
  id: chatId,
  extraBody,
});

await session.files.write("/session/app-context/customer-history.csv", stream, {
  mediaType: "text/csv",
  source: "app-context",
});
```

The next `streamHarness({ session, messages })` call can reference the staged
file in a short notice, or the developer can mention it through an Input Type or
message. This is useful for background uploads, app-side imports, and files that
arrive between chat turns.

## Isolation Rule

Two sessions do not see each other's files by accident. Shared state only appears through an explicit Persistent Dir or through an app tool that deliberately reads shared data.

This keeps the developer from debugging strange cases where one user's agent changed another user's working files.

## Extra Body Context

`extraBody` is app-defined. Little Harness treats it as host metadata passed to tools, Persistent Dir callbacks, events, and traces, not as a built-in identity system.

```ts
extraBody: {
  userId: "user_123",
  teamId: "team_456",
  role: "account_manager",
}
```

The developer decides which fields matter for storage, tools, policy, and audit.

## Experimental Context Policy

The SDK stays off unless `contextPolicy` is configured. Its four controls are `triggerTokens`,
`keepLastTurns`, `summaryModel` (`false` means trim only) and `maxCompactionCostUsdPerSession`
(default $0). A host supplies durable checkpoints and admission before paid summaries. Canonical
messages stay caller-owned; model views can reuse validated immutable prefixes across turns.

The normal `maxOutputTokens` option on the Harness, turn hook or call is also the context output
reserve. Managed hosts use the model maximum only when it is absent. See the package's
`docs/context-policy.md` for projection, replay and paired managed-integration limitations.

Soft triggers calibrate from the session's last measured model input and the byte estimate of
that same request. Missing or incompatible samples use conservative bytes; the hard-window
bound remains conservative. Short image/file inputs pass unchanged, and media remains retained
when older text is projected. Built-in local-host paid summaries with a durable local store
are a later item; the plain SDK default supplies trim only.
