---
title: Local World
description: Zero-service local development for durable workflow runs.
---

Local World is the planned development backend for Little Workflow.

It should let developers compile, run, inspect, replay, and reset workflows without Postgres, Redis, S3, or cloud accounts.

```ts
const runtime = createRuntime({
  world: localWorld({ dataDir: ".little-workflow" }),
});
```

## Directory Layout

```txt
.little-workflow/
  config.json
  pgdata/
  events/
    run_123.export.jsonl
  state/
    run_123.snapshot.json
  streams/
    run_123.default.jsonl
  blobs/
    sha256/
      ab/
        cdef...
  artifacts/
    art_123.json
  skillpacks/
  plugins/
  sandboxes/
  logs/
```

The metadata store targets PGlite. Artifacts live as content-addressed local files plus artifact manifests. Queue execution is in-process for local development.

## Compatibility Goal

Code should depend on runtime interfaces, not the local implementation:

- `MetadataStore`
- `ArtifactStore`
- `QueueBackend`
- `StreamStore`
- `SkillStore`
- `PluginStore`

That keeps examples portable from Local World to production adapters.

## Limits

Local World is not production-grade:

- no distributed workers
- no production locking
- no multi-tenant isolation beyond directory separation
- no presigned multipart upload flow
- in-process queue state can be lost if jobs were not committed first

The first alpha demo should prove kill-and-resume behavior: stop a run mid-flight, restart, replay persisted events, and continue without re-calling completed model or tool steps.
