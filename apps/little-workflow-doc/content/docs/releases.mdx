Little Harness, Little Workflow and the LittleDB client are published as
`0.2.0-alpha.4`. This is the first public `@little-stack/littledb` release.
All three packages share one version number. The LittleDB client needs a LittleDB
account; the LittleDB server is not open source. Little Compute remains unpublished.

| Product | Package | Status | Command |
| --- | --- | --- | --- |
| [Little Harness](/docs/harness) | `@little-stack/harness` | Published `0.2.0-alpha.4` | `little-harness` |
| [Little Workflow](/docs/workflow) | `@little-stack/workflow` | Published `0.2.0-alpha.4` | `little` |
| [LittleDB client](/docs/littledb) | `@little-stack/littledb` | First public release, `0.2.0-alpha.4` | `littledb` |
| Managed workspaces | Part of the LittleDB service | LittleDB account required | No standalone npm package |
| [Little Compute](/docs/compute) | `@little-stack/compute` | Unpublished | No public install path |

The SDKs require Node.js 22+ and AI SDK 7. Create a project
with `npx @little-stack/workflow@alpha setup my-app --littledb --yes --install --verify`,
then use `npx @little-stack/littledb@alpha login --url <LittleDB> --project <slug>`
with a LittleDB account. See [Setup](/docs/get-started/setup).

## Alpha.4 changes and migration

- **Breaking:** task and workflow tools are offered only when an agent can use
  them. To restore the previous tool list, set `taskTools: true, workflowTools: true`
  on `createHarness` with durable services available. The names remain reserved.
- Setup gains managed-model starters, starter skills and additive existing Node
  setup. The LittleDB CLI provides browser `login`, agent-folder `deploy` and `chat`.
- Harness gains per-instance folder context, shorter tool lists, tool budgets,
  virtual `/tmp`, command-runner denial, trace value redaction and private spill storage.
  Both SDK packages carry their release-matched coding-agent skills and package docs.
- Tracing Worlds upload workflow plans in the background; `flush()` and `shutdown()`
  include that work. Content suppression sends structural plans, not full anonymization.
- Context compaction is opt-in through `contextPolicy`; it projects the model view
  while retaining canonical history. The SDK default is off. Workflow projects prior
  tool rounds within its current task rather than summarizing the task itself.

## Package names

Harness and Workflow moved from `little-harness` and `little-workflow` to
`@little-stack/harness` and `@little-stack/workflow` in alpha.2. Replace dependency
and import names, including subpaths. The old published packages remain installable.
The LittleDB client was formerly `@little-workflow/littledb`; from alpha.4 it
uses `@little-stack/littledb` and the `littledb` command.

## What UNRELEASED means

UNRELEASED identifies source-only functionality outside the published SDK/client
release, including Little Compute. The hosted LittleDB service is separate from
the client; installing the client does not install the LittleDB server.

## The `v0.1.0-alpha` URL segment

The Harness and Workflow documentation keeps this historical URL segment so
existing links work. It is not the npm package version; alpha.4 package versions
are `0.2.0-alpha.4`.
