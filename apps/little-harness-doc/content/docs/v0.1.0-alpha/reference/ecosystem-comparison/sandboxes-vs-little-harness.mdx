---
title: Sandboxes Vs Little Harness
description: How E2B, Daytona, Vercel Sandbox, Modal, and Cloudflare Sandbox compare with Little Harness.
---

Sandbox providers solve a crucial layer: give the agent a safe computer.

Little Harness sits above that layer. It can use a sandbox as a backend, but it also needs to define messages, tools, skills, artifacts, Persistent Dirs, commit timing, and traces.

## Use A Sandbox Provider When

- the agent must run untrusted code
- the app needs isolated Linux processes
- the environment needs files, command execution, ports, terminals, or previews
- snapshots or reproducible dev environments matter
- cloud isolation is the hardest unsolved problem

## Use Little Harness When

- the app needs a product-agent runtime, not only compute
- large tool outputs should become artifacts
- selected folders should commit back to app storage
- the host app needs traceable file and tool behavior
- the same API should work across just-bash, E2B, Vercel Sandbox, Modal, or another backend

## Provider Notes

| Provider | Strongest Fit | Little Harness Gap |
|---|---|---|
| E2B | Agent-native Linux sandbox with filesystem, commands, snapshots, metrics, and MCP patterns. | No app-level Persistent Dir or AI SDK stream contract by itself. |
| Daytona | Reproducible dev environment sandboxes, git helpers, commands, volumes, snapshots. | More cloud dev environment than product-agent harness. |
| Vercel Sandbox | Secure microVM execution for Vercel apps, files, commands, ports, policies, persistence. | Needs harness semantics above the sandbox. |
| Modal Sandbox | Remote code execution with snapshots and filesystem APIs. | Persistence is environment snapshot-oriented, not app directory-oriented. |
| Cloudflare Sandbox | Worker-controlled containers with files, commands, previews, terminals, file watching. | Platform-specific runtime primitive. |

## Core Difference

| Question | Sandbox Provider | Little Harness |
|---|---|---|
| Main abstraction | Isolated compute environment. | Managed agent session. |
| Agent loop | Usually outside the sandbox. | Part of the harness runtime. |
| Files | Sandbox filesystem. | `/session/`, `/artifacts/`, `.agents/skills/`, `/persistent/`. |
| Persistence | Snapshots, volumes, names, or provider storage. | App-owned load/store callbacks and commit boundaries. |
| Best fit | Running code safely. | Letting an agent work safely inside an app. |
