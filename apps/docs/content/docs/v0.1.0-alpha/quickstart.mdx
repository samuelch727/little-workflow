The quickstart shows the local developer loop: define a workflow, run it in Local World, and inspect the events and artifacts. This covers a single workflow — see [Orchestrator](/docs/v0.1.0-alpha/author-workflows/orchestrator) for multi-workflow composition.

## Install

```sh
pnpm add little-workflow
```

Local World uses `better-sqlite3` for its embedded event store. In pnpm v10 projects, approve that native build at the consuming app root before running workflows:

```yaml
# pnpm-workspace.yaml
onlyBuiltDependencies:
  - better-sqlite3
```

## Define The Workflow

```ts
import { tool } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";
import {
  createLittleWorkflow,
  createToolRegistry,
  localWorld,
  model,
  runWorkflow,
} from "little-workflow";

// ── Tools ──────────────────────────────────────────────────────────────────
const tools = createToolRegistry({
  lookupCustomer: tool({
    description: "Look up customer metadata by account ID.",
    inputSchema: z.object({ accountId: z.string() }),
    execute: async ({ accountId }) => ({ accountId, plan: "enterprise" }),
  }),
});

// ── Model slots ─────────────────────────────────────────────────────────────
// Slot id is auto-derived from the model name ("gpt-4o-mini").
// If the model is in the bundled registry, description is auto-filled.
// Supply your own description to override or clarify.
const fastModel = model(openai("gpt-4o-mini"));

// ── Workflow definition ──────────────────────────────────────────────────────
const summarizeTicket = createLittleWorkflow({
  id: "support.summarize-ticket",
  description: "Summarize a support ticket and classify its severity.",

  inputSchema: z.object({
    ticketId: z.string(),
    transcript: z.string(),
  }),
  outputSchema: z.object({
    summary: z.string(),
    severity: z.enum(["low", "medium", "high"]),
  }),

  // Execution model options the planner can reference in LWIR steps.
  models: [fastModel],

  // Planner — required. Runs in the default workflowHarness unless overridden.
  planner: {
    model: openai("gpt-5"),
    system: "You design support-ticket summarization workflows.",
  },

  // worker: optional. Defaults to the SDK workflowHarness.
  // Override only if you need a custom harness or worker-specific skills.

  // Tools the LWIR can reference (names in the registry above).
  globalTools: ["lookupCustomer"],

  // Memory mounts — optional; these are the defaults.
  memory: {
    workflow: "rw",  // planner reads/writes /mnt/memory/workflow/
    org: "ro",       // planner reads /mnt/memory/org/ (read-only)
  },
});
```

`models` lists the execution model options the planner can assign to LWIR steps. The planner's own model is configured under `planner.model` and is separate. See [AI SDK Native](/docs/v0.1.0-alpha/author-workflows/ai-sdk-native) for the `model()` factory and [Create A Workflow](/docs/v0.1.0-alpha/author-workflows/create-workflow) for all config fields.

## Run It Locally

```ts
const result = await runWorkflow({
  world: localWorld({ dataDir: ".little-workflow" }),
  workflows: summarizeTicket,   // single WorkflowDefinition → planner runs
  tools,
  input: {
    ticketId: "TCK-123",
    transcript: "Customer reports intermittent billing export failures...",
  },
  timeout: "10m",
});
```

Passing a single `WorkflowDefinition` to `workflows` runs the planner for that workflow. Passing an array switches to orchestration mode (requires an `orchestrator` config). See [Orchestrator](/docs/v0.1.0-alpha/author-workflows/orchestrator).

Local World stores metadata, events, and artifacts under `.little-workflow/`. No Postgres, Redis, or S3 required.

## Inspect The Run

```bash
little events run_123
little replay run_123
```

`little events` dumps the run's event log (one JSON event per line). `little replay` reconstructs run state from persisted events without re-calling models, tools, or external APIs.

## What The Runtime Produces

The planner runs in a `workflowHarness` session. It produces LWIR — a validated, canonical JSON workflow graph. The runtime then executes each step through the worker harness:

- `ai.generate` steps run in an AI agent loop with the step's tool allowlist.
- `code.run` steps execute directly; your code receives `{ input, tools }` and can call registered tools without going through the model.
- `tool.call` steps invoke a single named tool from the registry.

The compiled artifact (LWIR + capability snapshots) is the `WorkflowVersion`. Durability guarantees: completed steps are never re-executed on resume.
