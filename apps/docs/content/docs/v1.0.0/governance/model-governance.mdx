LWIR stores model slot IDs, not executable AI SDK model objects.

Developer authoring can use familiar AI SDK primitives, but production workflow versions need locked model metadata.

```ts
const planner = model(openai("gpt-5.4"), {
  description: "Planner model for compiling and repairing LWIR.",
  role: "planner",
  useFor: ["workflow_planning", "schema_reasoning", "policy_repair"],
  qualityTier: "reasoning",
  costClass: "high",
  capabilities: ["text", "structured", "tools"],
  defaults: {
    temperature: 0,
    maxOutputTokens: 12000,
  },
  allowOverrides: ["maxOutputTokens", "providerOptions.gateway.tags"],
  limits: {
    maxCostUsdPerCall: 2,
    maxCallsPerRun: 20,
  },
});
```

## Selection Rule

The orchestrator chooses among model slots using enforceable fields:

- role
- capabilities
- quality tier
- latency class
- cost class
- data policy
- budget policy
- step risk
- allowed destinations

Advisory fields can influence explanations and ranking, but cannot satisfy policy requirements.

## Lock Metadata

WorkflowVersion locks should record:

- slot ID
- selection metadata hash
- source kind
- resolved provider/model identifier when introspection allows it
- AI SDK and provider package versions
- default settings
- allowed override policy
- pricing metadata version
- adapter API mapping

If middleware hides the underlying model identity, production mode should require explicit `providerId`, `modelId`, and `modelSource`.
