---
title: Pipelines
description: Compose workflow definitions without silent schema coercion.
---

`chainWorkflows()` composes workflow definitions into an ordered pipeline.

Each child workflow still compiles to its own WorkflowVersion. The pipeline compiles to a parent WorkflowVersion whose steps invoke those child workflows. That keeps retry, replay, fork, artifacts, and audit visible per workflow node.

## Basic Pipeline

```ts
const candidateRanking = createLittleWorkflow({
  id: "candidate.rank",
  description: "Rank reviewed candidates against the provided criteria.",
  inputSchema: candidateReview.output.schema,
  output: Output.object({
    schema: z.object({
      candidateRanking: z.array(
        z.object({
          candidateId: z.string(),
          ranking: z.number(),
          reason: z.string(),
        }),
      ),
    }),
  }),
  models: [reasoningModel, verifierModel],
});

const pipeline = chainWorkflows([candidateReview, candidateRanking], {
  schemaPolicy: "fail_on_schema_mismatch",
});
```

## Schema Policy

```ts
type PipelineSchemaPolicy =
  | "fail_on_schema_mismatch"
  | "allow_explicit_transform"
  | "ai_suggest_transform_requires_approval";
```

`fail_on_schema_mismatch` is the default. The runtime must never silently coerce one workflow output into another workflow input.

## Explicit Transform

```ts
const pipeline = chainWorkflows([candidateReview, candidateRanking], {
  schemaPolicy: "allow_explicit_transform",
  transforms: [
    transform({
      from: candidateReview,
      to: candidateRanking,
      input: candidateReview.output.schema,
      output: candidateRanking.inputSchema,
      run: (reviewOutput) => ({
        candidates: reviewOutput.candidates,
      }),
    }),
  ],
});
```

Transforms need input and output schemas, stable hashes, and deterministic execution. AI-suggested transforms can draft proposals, but validation and approval still happen before execution.

## AI-Suggested Transform

When the schema policy is `ai_suggest_transform_requires_approval`, the pipeline drafts a bridging transform itself and pauses for human approval before executing it.

This draft is a **pipeline-level** task. Each child workflow already has its own planner model for planning that child; the pipeline should not reach down into a child's planner for an upper-level concern. Pass a dedicated `transformModel` instead.

```ts
const pipeline = chainWorkflows([candidateReview, candidateRanking], {
  schemaPolicy: "ai_suggest_transform_requires_approval",
  transformModel: model(openai("gpt-5"), {
    role: "planner",
    qualityTier: "reasoning",
    description: "Pipeline-level model for proposing schema transforms between workflows.",
  }),
});
```

`transformModel` is required when `schemaPolicy` is `ai_suggest_transform_requires_approval`; it is ignored for the other two policies (no AI work is needed). The model is governed the same way as any other `model()` slot — its identity, defaults, and limits are locked into the pipeline's parent WorkflowVersion.

The draft transform is recorded as an artifact and stays unexecuted until an approver signs off. Approval freezes the transform into the WorkflowVersion lock so future runs of the same pipeline use the same bridge deterministically.
