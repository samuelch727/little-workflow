Little Harness is a local-first agent runtime for teams that want useful sessions before choosing managed hosting, sandboxes, artifact plumbing, or workflow orchestration. Give it a Local Host, model, system prompt, tools, skills, and optional persistent directories; it creates or resumes the session, exposes the right harness directories, captures traces, and keeps each execution isolated by default.

```ts
import { openai } from "@ai-sdk/openai";
import type { UIMessage } from "ai";
import { createHarness, localHost, skill, streamHarness } from "little-harness";

const system = "You help account teams find practical renewal risks.";

const harness = createHarness({
  host: localHost({ dataDir: ".little-harness" }),
  model: openai("gpt-5"),
  system,
  tools: { searchDocs, queryCustomers },
  skills: [skill("./skills/domain-glossary")],
});

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamHarness({
    harness,
    messages,
  });

  return result.toUIMessageStreamResponse();
}
```

For interactive chat, use `streamHarness()` and return an AI SDK-compatible UI
message stream. For workers, tests, cron jobs, or Little Workflow nodes, use the
same harness with `generateHarness()` and await the completed result.

```ts
import { Output } from "ai";
import { generateHarness } from "little-harness";

const result = await generateHarness({
  harness,
  type: "support.ticket_triage",
  input: ticket,
  output: Output.object({ schema: triageSchema }),
});

console.log(result.output.priority);
console.log(result.trace.id);
console.log(result.trace.path);
```

## The Default Runtime

Every `streamHarness()` or `generateHarness()` call runs inside an isolated session workspace. If you do not pass a session key, Little Harness creates an ephemeral session for that request. If you pass a stable session key, such as your app's chat id, Little Harness continues the same private workspace.

One session never runs more than one turn at the same time. Local Host queues same-session calls by default, while different sessions can run concurrently.

The default filesystem layout is small and predictable:

| Path | Purpose |
|---|---|
| `/session/` | Private workspace for the current session |
| `/artifacts/` | Large tool outputs and generated files |
| `.agents/skills/` | Read-only skill directories, relative to the harness working directory |
| `/persistent/` | Opt-in developer-backed persistent dirs |

Session files are useful for scratch work, intermediate notes, and generated outputs that only belong to the current conversation. Persistent files are only exposed when the app provides a backing store.

In Local Host, stable sessions are inspectable under `.little-harness/sessions/<session-id>/`.

## Continue A Session

Pass a stable session key to continue the same private workspace and trace. In chat apps, this is usually your app's chat, thread, or conversation id.

```ts
const result = streamHarness({
  harness,
  messages,
  session: chatId,
});
```

Continuing a session preserves the agent's working files and lets the host app show a single evolving thread. Starting a new session gives the agent a fresh workspace.

On the client, keep using ordinary AI SDK chat primitives.

```ts
import { useChat } from "@ai-sdk/react";
import { DefaultChatTransport } from "ai";

const { messages, sendMessage } = useChat({
  transport: new DefaultChatTransport({ api: "/api/chat" }),
});

sendMessage({ text: "Add the last three support incidents." });
```

## Stage Message Files

When the user sends files through chat, the app can stage those files into the
session before the model turn starts.

```ts
const harness = createHarness({
  host: localHost(),
  model: openai("gpt-5"),
  system,
  chat: {
    stageMessage: async ({ message, inputFiles, files }) => {
      const stagedFiles = await Promise.all(
        inputFiles.map((file) =>
          files.write(
            `/session/user-input/${message.id}/${file.safeName}`,
            file.content,
            { mediaType: file.mediaType },
          ),
        ),
      );

      return {
        stagedFiles,
        notice: "Uploaded files were staged into /session/user-input/.",
      };
    },
  },
});
```

The model should receive paths and short descriptions, not raw uploaded file
contents. The full files live in the harness filesystem where the agent can
inspect them with tools, shell commands, or scripts.

## Tools And Large Outputs

Little Harness accepts normal AI SDK tools. Keep tool return
values compact when they fit in context, and let tools write large results into
session files or artifacts when they do not.

```ts
import { tool } from "ai";
import { z } from "zod";

const queryCustomers = tool({
  name: "query_customers",
  description: "Query customer account data by account id.",
  inputSchema: z.object({
    accountId: z.string().optional(),
    query: z.string().optional(),
  }),
  execute: async (input, ctx) => {
    const rows = await customerDb.query(input);

    const file = await ctx.files.writeJSON(
      "/artifacts/tool/query-customers/result.json",
      rows,
    );

    return {
      preview: "Customer query exported for analysis.",
      path: file.path,
      bytes: file.bytes,
    };
  },
});
```

For large outputs, the agent receives a preview plus a stable path instead of a huge payload:

```ts
{
  preview: "42 matching support incidents. The largest risk themes are...",
  path: "/artifacts/tool/query-customers/result.json",
  bytes: 184392
}
```

The runtime supports ordinary developer tools: shell commands, JSON tools, SQLite queries, and Python-style scripts all fit the same session model.

## Skills

Skills are procedural instructions and reference material that can be disclosed without bloating the main system prompt.

```ts
const harness = createHarness({
  host: localHost(),
  model: openai("gpt-5"),
  system: "You help account teams prepare renewal briefs.",
  tools: { searchDocs, queryCustomers },
  skills: [
    skill("./skills/domain-glossary"),
    skill("./skills/customer-renewal-analysis"),
    skill("https://github.com/anthropics/skills", {
      skills: ["frontend-design"],
    }),
  ],
});
```

Little Harness injects skill descriptions at session start so the model knows what is available. Full skill bodies are staged read-only under `.agents/skills/<name>/`, which lets the agent inspect detailed instructions only when they matter:

```bash
cat .agents/skills/frontend-design/SKILL.md
```

## Persistent Dirs

Cross-session persistence stays off by default. Add Persistent Dirs when your app wants the agent to remember files across sessions, users, teams, or accounts.

For the common case where the model should save compact durable lessons itself,
use [Memory](/docs/v0.1.0-alpha/build-agents/memory). Memory is still backed by
a Persistent Dir, but it also injects a bounded `MEMORY.md` index into future
turns and exposes a `remember` tool by default.

```ts
const harness = createHarness({
  host: localHost(),
  model: openai("gpt-5"),
  system: "You help account teams prepare renewal briefs.",
  tools: { searchDocs, queryCustomers },
  persistentDirs: [
    {
      harnessDir: "/persistent/user",
      load: async ({ extraBody }) =>
        appStorage.loadFolder(`users/${extraBody.userId}/memory`),
      store: async ({ extraBody, changes }) =>
        appStorage.applyChanges({
          prefix: `users/${extraBody.userId}/memory`,
          changes,
        }),
    },
  ],
});
```

For writable Persistent Dirs, the model writes to the `harnessDir` inside the isolated session first. At the end of the agent turn, Little Harness computes the diff and calls `store()` with the changes. Read-only Persistent Dirs reject writes immediately.

`extraBody` is app-defined request context. Little Harness does not define auth, tenancy, or product shape; it forwards whatever the app passes to tools, Persistent Dir callbacks, events, and trace metadata.

Future advanced store shapes may receive a full folder snapshot instead of a diff, or expose lazy `list`, `read`, `write`, and `delete` operations for S3, R2, GCS, or application databases.

For Local Host, use `localDir()` when the backing source is a local folder.

```ts
import { localDir, projectDir } from "little-harness";

const harness = createHarness({
  host: localHost({ dataDir: ".little-harness" }),
  model: openai("gpt-5"),
  persistentDirs: [
    localDir({
      harnessDir: "/persistent/company",
      sourceDir: projectDir("./docs"),
      commit: "read-only",
    }),
    localDir({
      harnessDir: "/persistent/user",
      sourceDir: ({ extraBody }) =>
        `persistent/users/${extraBody.userId}/memory`,
      commit: "after-turn",
    }),
  ],
});
```

Plain relative `sourceDir` values resolve under `localHost({ dataDir })`.
`projectDir(...)` is the explicit way to expose project files and must resolve
inside `projectRoot`.

## Commit And Error Behavior

Use after-turn commits when you want persistence to happen only after the agent finishes its normal response.

```ts
const harness = createHarness({
  host: localHost(),
  model: openai("gpt-5"),
  system,
  tools,
  persistentDirs: [
    {
      harnessDir: "/persistent/user",
      load,
      store,
      commit: "after-turn",
    },
  ],
});

const result = streamHarness({ harness, messages, session, extraBody });
const finished = await result.finished;

if (finished.persistence.status === "failed") {
  // Show a warning, retry in the background, or page ops.
}
```

If a persistence commit fails, Little Harness does not inject that failure into the agent's normal context. The host app can inspect `finished.persistence.status`, notify the user, retry, or route the failed changes to support. Uncommitted files remain recoverable from the isolated session, and the trace records the commit failure for debugging.

## Artifacts And Exports

Artifacts are host-visible session paths for generated files and large tool
outputs. The agent can reference an artifact path in its response, and host
tools can promote artifacts into product records, reports, tickets, or
downloads.

```txt
/artifacts/tool/query_customers/turn_003/result.json
/artifacts/report/renewal-risk.md
/artifacts/data/incidents.sqlite
```

```ts
const saveReport = tool({
  name: "save_report",
  description: "Save a generated report into the app.",
  inputSchema: z.object({
    title: z.string(),
    artifactPath: z.string(),
  }),
  execute: async ({ title, artifactPath }, ctx) => {
    const file = await ctx.artifacts.read(artifactPath);

    return reports.create({
      title,
      content: file.text(),
    });
  },
});
```

Artifacts let the agent work with files that are too large for prompt context while keeping the app in control of what gets exported.

## Powered By just-bash

The first local runtime is powered by just-bash, a TypeScript virtual bash environment with an in-memory filesystem. The useful pieces are virtual and mountable filesystems, copy-on-write overlays, common shell, text, and data commands such as `rg`, `jq`, `sqlite3`, and `xan`, optional Python and JavaScript execution, network disabled by default, and Runtime Tool Bridge access to configured tools from `js-exec`.

just-bash helps protect against untrusted scripts inside the managed environment, not untrusted host hooks. Tools, storage hooks, and export callbacks are host app capabilities and should be scoped accordingly.

## Non-Goals

- No containers, microVMs, or raw execution environment required for the happy path.
- No artifact storage choice before the first agent works.
- No host filesystem paths exposed to the model by default.
- No accidental cross-session persistence.
- No Little Workflow dependency for users who only need an agent runtime.
