---
title: AI SDK Native
description: How Little Workflow accepts AI SDK primitives without giving the planner raw execution power.
---

Little Workflow should not hide the AI SDK. Developers should be able to pass AI SDK models, tools, output specs, provider options, and streaming settings directly into the control plane.

The runtime boundary is strict: AI SDK values are accepted while authoring, but LWIR stores model slots, capability refs, JSON Schemas, hashes, and policy snapshots.

## Model Slots

```ts
const reasoning = model(openai("gpt-5.4"), {
  description: "High-quality model for planning repair and evidence review.",
  role: "worker",
  useFor: ["hard_structured_output", "evidence_review"],
  qualityTier: "reasoning",
  latencyClass: "batch",
  costClass: "high",
  capabilities: ["text", "structured", "tools", "streaming"],
  defaults: {
    temperature: 0,
    maxOutputTokens: 4096,
  },
  allowOverrides: [
    "temperature",
    "maxOutputTokens",
    "providerOptions.gateway.tags",
  ],
  limits: {
    maxCostUsdPerCall: 0.5,
    maxCallsPerRun: 1000,
  },
});
```

`useFor`, `strengths`, and `avoidFor` are planner hints. Enforceable governance comes from closed fields such as role, capabilities, data classes, allowed destinations, budget limits, and approval requirements.

## Structured Output

The product spec uses AI SDK `Output.*` terminology for the target developer experience. Before runtime implementation, the adapter must verify the exact stable or experimental export names supported by the installed AI SDK version and lock that mapping in the WorkflowVersion.

The docs should not imply that an unstable AI SDK helper is safe to use without feature detection.

## Lifecycle Capture

Little Workflow wraps AI SDK lifecycle hooks so durable persistence happens before user callbacks:

- `onStepFinish`
- `onFinish`
- telemetry hooks
- retry and repair hooks where supported
- stream part capture from `fullStream`

User callbacks are useful for app behavior. They are not the source of durable truth.

## Production Model Identity

Production model locks need a resolved provider and model identity. If middleware hides the underlying model object, `model()` should provide explicit `providerId`, `modelId`, and `modelSource` metadata before the slot can be used in production.
