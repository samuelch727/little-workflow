---
title: Glossary
description: Short definitions for the primitives, policies, and runtime objects used across the docs.
---

A one-line definition per term, with links to the page that owns the full treatment.

## A

**Artifact** — A stored payload (prompt, response, file, log, generated output, tool result) addressed by an artifact ID with a manifest and a content-addressed blob. See [Inspect Runs](/docs/v1.0.0/run-inspect/inspect-runs).

## C

**Capability** — A governed runtime reference to an executable side effect (tool, model call, network destination, secret access). The planner can reference capabilities the developer passed in; the runtime invokes them.

**Capability Firewall** — The rule that the planner can only reference tools the developer passed into the workflow definition; it cannot invent new tool references. See [Capability Firewall](/docs/v1.0.0/governance/capability-firewall).

## D

**Definition (WorkflowDefinition)** — The ergonomic TypeScript authoring object passed to `createLittleWorkflow()`. Declarative and free of runtime infrastructure. See [Create A Workflow](/docs/v1.0.0/author-workflows/create-workflow).

## E

**Event Log** — The append-only record of facts and pointers for a run. Replay rebuilds state from the event log without re-calling external systems. See [Inspect Runs](/docs/v1.0.0/run-inspect/inspect-runs).

**Evidence Reference** — A typed locator (`artifactId`, `locator`, `claim`, `sourceStepPath`) that lets a downstream step cite a specific span of source material. See [Quickstart](/docs/v1.0.0/quickstart).

## F

**Fork** — A new run derived from a checkpoint or previous run. Forks can change inputs, model slot mapping, prompts, policy, or output schema; the result is a new WorkflowVersion with provenance back to the parent. See [Durability](/docs/v1.0.0/run-inspect/durability).

## L

**LWIR** — Little Workflow Intermediate Representation. The canonical JSON runtime format that workers execute. Hashable, canonicalizable, and immutable once registered. See [LWIR v0.1](/docs/v1.0.0/reference/lwir-reference).

**Lease Token** — A monotonic token issued through compare-and-set when a worker acquires a step attempt. Every write a worker makes during the lease must include the token; stale tokens are rejected. See [Durability](/docs/v1.0.0/run-inspect/durability).

**Local World** — The zero-service local development backend. Uses PGlite for metadata, filesystem for artifacts, and an in-process queue. See [Local World](/docs/v1.0.0/run-inspect/local-world).

## M

**ModelSlot** — A governed reference to a model with role, capabilities, quality tier, cost class, allowed overrides, and limits. LWIR stores slot IDs; the runtime resolves the slot to a model at call time. See [Model Governance](/docs/v1.0.0/governance/model-governance).

## O

**OrchestrationRequest** — The canonical, signed/versioned planner input. Declarative; contains the goal, safe capability metadata, model slots, data policy, approval rules, budgets, and the requested output schema. See [Core Mental Model](/docs/v1.0.0/mental-model).

## P

**Plugin** — A manifest-first package that contributes models, tools, skills, policies, adapters, modules, or UI panels to a runtime.

## R

**Replay** — Reconstructs run state from the event log without calling models, tools, shell, code, or external APIs. See [Durability](/docs/v1.0.0/run-inspect/durability).

**Retry** — Re-executes a failed step using the same WorkflowVersion and input. Requires idempotent commits or an explicit `sideEffectKey`. See [Durability](/docs/v1.0.0/run-inspect/durability).

**Run** — One execution of a WorkflowVersion with one input packet and one runtime policy snapshot. See [Run A Workflow](/docs/v1.0.0/run-inspect/run-workflow).

**runWorkflow** — The one-shot entry point that provisions a runtime, executes a single run, and returns the result. See [Run A Workflow](/docs/v1.0.0/run-inspect/run-workflow).

## S

**SideEffectKey** — A stable key the runtime uses to deduplicate external commits across retries. The downstream system sees the same key and refuses to apply the change twice.

**Skill** — Reusable procedural guidance packaged as a `SKILL.md` file plus optional references, schemas, assets, and scripts. Skills are context, not authority — they cannot grant capabilities. See [Skills And SkillPacks](/docs/v1.0.0/author-workflows/skills).

**SkillPack** — A skills-only plugin preset. Bundles related skills with manifest and lock metadata so teams can share guidance.

**StepAttempt** — One attempt to execute a step within a run, including the fan-out item key when applicable.

## T

**Tool** — A plain AI SDK `tool()` definition. Lives in `model().tools` for planner-time use or in `globalTools` for workflow execution. The runtime invokes only tools recorded in the compiled WorkflowVersion.

## W

**WorkflowVersion** — A registered, immutable LWIR document plus capability manifest hash, policy version hash, skill and plugin lock snapshots, compiled expression plan, validation result, and cost/risk estimate. Workers verify the locks before execution. See [Core Mental Model](/docs/v1.0.0/mental-model).
