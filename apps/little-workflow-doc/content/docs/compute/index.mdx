Little Compute is a self-hostable control plane for repository-aware agents. It lets a
Little Harness parent create durable child Tasks, attach isolated compute only for tool
bursts, preserve workspace progress between attachments, and converge results with clean
verification.

<Callout title="Refocus, 2026-10-23">
  Little Compute is the self-hosted engine behind the stack's
  [workspaces](/docs/how-they-fit#workspaces) feature, not a product of its own.
  Managed workspaces come with LittleDB's hosted service (private for now). Little Compute's
  control plane is frozen: what is merged keeps working, and nothing new is added
  to it. See `packages/little-compute/FROZEN.md` in the source checkout.
</Callout>

```txt
Operation
  -> immutable Task Scope
    -> Task
      -> Attempt + Harness Session + File Snapshot generation
        -> zero or more sequential Sandbox Leases
          -> fenced execs
  -> convergence and fresh verification
```

## Product boundary

Little Compute owns agent Tasks, retry Attempts, fluid Sandbox Leases, admission, budgets,
repository lineage, typed Publications, convergence, and provider fencing. It does not
reimplement a container runtime, hypervisor, Kubernetes node scheduler, object store,
workflow engine, or browser protocol.

The core optimization target is time from one user intent to one verified, reviewable result
across many cooperating agents—not the largest number of empty generic containers.

## Start here

Little Compute is operated, not imported: an operator runs it on their own
machine or cluster, and Little Harness agents use it through optional ports. It
is not publicly installable yet; the operator steps below need access to an
unpublished source checkout.
